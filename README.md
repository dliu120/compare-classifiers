# Decision Bakeoff

Compares hosted decision APIs with an Own build that prompts a general LLM to emulate the
same API, on text and image inputs. Every Provider is called through one surface,
TypeSafe's System One contract (`state` plus named `noul`, `choice`, and `score` questions,
probabilities back), so the comparison is apples to apples.

Vocabulary lives in [CONTEXT.md](CONTEXT.md). The decisions that shape the harness are in
[docs/adr](docs/adr): System One is the canonical surface, OpenAI direct is the reference
Route for the Own build, Non-answers score as wrong, and Confidence is recomputed from
probabilities with TypeSafe's documented formulas.

Own build query options: `max_in` (input token cap applied to the State, the sweep
variable that mirrors each vendor's context limit), `effort` (none, low, medium, high,
xhigh, max), `cap` (max output tokens; leave unset unless you are studying truncation),
`mode` (`probabilities`, `discrete`, or `logprobs`, the last only on the OpenAI Route with
`effort=none`), `samples` (independent calls averaged), and `via` (a running
`bakeoff serve` base URL).

Decision APIs expose no output cap, temperature, or reasoning budget, so those knobs only
exist on the Own build. The Copilot Route makes one attempt per request and a Run stops at
its first 429, per ADR 0002.

## Setup

```sh
uv sync --all-extras
cp .env.example .env   # fill in the keys you have; the file is gitignored
```

Prices come from `src/bakeoff/pricing.py` (existing list prices read on 2026-10-06;
Microsoft-Decision-1 on 2026-10-10; Luna long-context rates on 2026-10-12). Spend is
capped per `run` by `--budget` or `BAKEOFF_BUDGET_USD` (default 50 USD).

## Commands

```sh
uv run bakeoff probe                      # one sample request to every configured Provider
uv run bakeoff gen smoke --limit 20       # build the smoke Families under data/smoke
uv run bakeoff run -p jev -p 'ownbuild/copilot/gpt-6-luna?effort=none' \
    -f routing-synthetic -f banking77 -f longstate-32k -f rendered-images --limit 20 --budget 2
uv run bakeoff report                     # runs/report.md and runs/pareto.svg
uv run bakeoff serve --spec 'ownbuild/openai/gpt-6-luna?effort=none'   # POST /v1/systemone
```

Runs are resumable: a Case already stored for a Run is skipped. Results go to
`runs/bakeoff.sqlite`, raw requests and responses to `runs/raw/<run>.jsonl` with images
replaced by their hash and credentials redacted.

The published snapshot contains benchmark code, public/synthetic Cases, and measured
results—not account credentials or access to a running deployment. Archived responses
have request identifiers and unrelated account/provider metadata removed. Error text is
sanitized; database files are rebuilt from their retained rows. `.env`, local caches,
deployment records, audit files, and previous Git history are not included.

## Data

Families live at `data/<family>/cases.jsonl` with a `family.json` manifest recording track,
source, license, and whether references are Gold (human) or Silver (model). The smoke slice
under `data/smoke` holds BANKING77, CLINC150, and When2Call subsets, a synthetic
support-routing Family generated through aiproxy and filtered by a second model's
agreement, and rendered receipt, screenshot, and color-card images with Gold by
construction. The `longstate-*` Families (8k to 256k tokens of synthetic
tickets with one decisive needle) are deterministic and regenerated by `gen smoke`, so they
are not tracked in git.

## Questions sent to Providers

Each Case supplies one State (a customer message, a structured ticket list, or text with
an attached image) and one or more named Questions. The request includes each Question's
instructions and, where applicable, its Options or ordered Levels. Reference Answers
stay in the harness for scoring; they are not sent to the Provider.

### Question types

| Type | What the Provider is asked to decide | Answer shape |
|---|---|---|
| **Choice** (`choice`) | Select one named Option, such as the team that should handle a ticket. `criteria` maps Option names to descriptions (or `null`). | A selected `choice` and a `probabilities` map over the Options. |
| **Noul** (`noul`) | Answer a yes/no Question, such as whether a message is urgent. | `noul`: the probability of yes, from 0 to 1. |
| **Score** (`score`) | Assess a State against ordered Levels, such as calm → frustrated but civil → very angry. `criteria` lists Levels lowest first. | Probabilities keyed by zero-based Level index and `score`, the probability-weighted index. |

The [recorded three-type Foundry probe](runs/foundry-live-smoke.json) shows a complete
request and response for a customer whose Stripe integration has been failing for three
days: choose billing/technical/sales, assess frustration on three Levels, and decide
whether the message conveys urgency. This is a connectivity example, not a Case in the
119-Question smoke ranking. The [canonical schema](src/bakeoff/systemone.py) defines the
types; adapters translate them to each API's wire format.

### Input-length sweep and additional available Families

The [input-length sweep](docs/input-cap-sweep-2026-10-06.md) repeats the same two
long-ticket Questions at State targets of 8k, 16k, 24k, 32k, 64k, 128k, and 256k tokens.
Each length has six deterministic Cases, with the target ticket near 10%, 50%, or 90%
of the list: 12 Questions per evaluated length. This tests retrieval and input coverage,
not open-ended question answering. [Generator](src/bakeoff/datasets/longstate.py);
[archived 32k request/response examples](runs/raw/openai-decisions-gpt-6-luna__longstate-32k.jsonl.gz)
(gzip JSONL).

Two more Families are available under `data/smoke` but **do not contribute to the reported
smoke ranking or input-length sweep**:

- [CLINC150 Cases](data/smoke/clinc150/cases.jsonl#L1): one **Choice** over 150 intents
  plus `oos` (out of scope).
- [When2Call Cases](data/smoke/when2call/cases.jsonl#L1): given a user question and
  available tool definitions, one **Choice** among `direct`, `tool_call`,
  `request_for_info`, and `cannot_answer`. This selects a response type; it does not
  execute a tool.

## Scoring

Accuracy counts every Non-answer as wrong. Choice is judged on the selected Option, Noul
at 0.5, Score on the most probable Level. Reports show chance-corrected accuracy, macro-F1,
ECE and Brier on the recomputed probabilities, non-answer rate by cause, p50 and p95
latency of the answering attempt, cost per 1k cases from reported usage, the share of Cases
over a Provider's documented input limit, paired bootstrap intervals and McNemar tests
against the best Run, and a Pareto chart of accuracy against cost.

## Status

**Microsoft-Decision-1 was tested through Foundry.** The public repository does not
provide a hosted endpoint or deployment access. Use your own Foundry resource,
deployment alias, and authorized Entra identity; see [setup](docs/foundry-api.md).

On the same 40 short-text Cases (80 Questions), the final Foundry pass scored **74/80
(92.5%)**, versus **75/80 (93.75%)** for a fresh GPT-6 Luna own build through Copilot.
Median request latency was **0.27 s versus 3.86 s**; estimated list-price cost was
**$0.0171 versus $0.2634 per 1k requests**. This small difference in quality does not
establish a winner. Foundry is text-only and rejected every tested 24k-and-larger State:
full-smoke accuracy was **74/119 (62.2%)**, with 39 Non-answers and unknown overall cost.
Repeated short-text passes scored 73/80, 73/80, and 74/80.
[Comparison, calibration, repeatability, and limits](docs/foundry-comparison-2026-10-10.md).

**Input-cap sweep takeaway:** on this small synthetic needle-retrieval benchmark,
gpt-6-luna (OpenAI Decisions) was fastest among the three configurations with 84/84 correct
and no Non-answers: 0.66 s median, versus 2.27 s for gpt-6-luna (copilot) and 2.36 s for
gpt-6-luna (openai), both own builds at a 256k input cap. Estimated list-price costs were
$7.5807, $6.2783, and $6.3596 per 1k requests, respectively, including reported cache
discounts. Smaller caps cost less but lost accuracy; fast HTTP rejections are not fast
useful answers. The October 12 UTC resumption fills Cloudflare's shorter-input coverage:
Clef scored 36/36 at 8k–24k; Clef-flash scored 33/36, with all three misses at 24k.
This is not a general classifier ranking; see the
[executive summary and limitations](docs/input-cap-sweep-2026-10-06.md#executive-summary).

**Large-context extension, 2026-10-12 UTC** (October 11 Pacific). The Luna own build
through Copilot was sent full States with **no local input cap**, reasoning effort `none`,
and no output cap. Six Cases at each length test needles near 10%, 50%, and 90%, with
two Questions per Case:

| State target | HTTP 200 requests | Right | Wrong | Non-answers | Median s |
|---|---|---|---|---|---|
| 512k | 6/6 | 12 | 0 | 0 | 5.36 |
| 768k | 6/6 | 10 | 2 | 0 | 9.30 |
| 900k | 0/6 | 0 | 0 | 12 | 3.39 (rejections) |

At 768k, the two wrong team choices targeted security tickets near 50% and 90%; all six
data-breach Questions were correct. At 900k, the proxy returned HTTP 502 wrapping an
upstream HTTP 400: the prompt exceeded **872,000 tokens**. This is a Route limit, not
evidence of Luna reasoning incorrectly at 900k. Clef and Clef-flash each rejected all
18 larger-input requests with HTTP 413. OpenAI Decisions and the direct OpenAI own build
returned HTTP 401 for every request: **authentication-blocked, not a measured context
limit or quality result**.

Finding a needle in these templated tickets is not proof of equally strong reasoning over
arbitrary long documents. These are single passes, not an exact breakpoint measurement.
Known estimated cost for this update is **$1.6440** ($0.1064 for the shorter CLEF cells
and $1.5377 for the successful large-context Copilot calls); failed requests without
reported usage have unknown cost, not zero.

**What stands out**

- OpenAI Decisions is the only hosted decision API that handled every length through 256k,
  and it did so in about a second per request.
- Jev is perfect at 8k and 16k and rejects 24k, so its usable limit sits between 16k and 24k
  of our tokens despite the documented 32k.
- Foundry also answered 8k and 16k perfectly and rejected 24k onward with HTTP 422.
  Full-prompt limits and tokenizer differences mean the State-only `Over cap` indicator
  does not mark every rejected request.
- Liquid d1 starts missing needles at 16k, well under its 64k limit, and rejects 64k and above.
- The historical Clef results are accurate past the documented 64k window but pay in
  latency: 20 to 60 seconds per request at 64k and 128k, with rejection at 256k.
  The new 8k–24k cells fill the earlier daily-allowance gap; Clef-flash missed three
  Questions at 24k. Larger-input rejection errors now name 65,536 tokens for Clef and
  24,576 for Clef-flash. These mixed-date observations do not establish today's accuracy
  or acceptance at the historical larger lengths.
- In the historical sweep through 256k, the own build on GPT-6 Luna is perfect whenever its
  input cap covers the State, on either Route, at lower estimated cost but higher latency
  than OpenAI Decisions. The new uncapped Copilot run misses two Questions at 768k.
